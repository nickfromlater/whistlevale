Your name travels with your work

A small credit, chosen by the contributor. No floating labels over the railway.

One format, across contribution types

Layouts, objects, trains, rooms and shared works can carry credits. Use a chosen public name; a pseudonym without a link is welcome. Keep earlier credits when adapting work. Profile links use validated handles on GitHub, X or Bluesky.

"credits": [
  {"name": "Your chosen public name", "platform": "github", "handle": "your-handle"}
]

This is a format example, not a credit to copy unchanged. Read the attribution contract for limits, source notes and corrections.

Discoverable in the house; preserved in exports

More → The builders lists contributors and their work. A train’s credit appears in the cabinet; a selected building’s credit appears in the editor inspector. Want to contribute? opens a quiet guide in the same More panel.

Validated credits survive saved layouts, duplication, undo/redo, JSON import/export and playable HTML. Shared data is embedded into the page and portable exports. There are no accounts, background fetches or new animation-loop tasks.

A contribution’s journey

  1. Describe the idea

    Choose a small addition or agree on a proposal for a larger one. Say what you want to make, where it belongs, and which public credit you want.

  2. Follow the recipe

    Use npm run contribute -- train or building. The command names the files, recipe and checks; --list --json exposes every route for agents.

  3. Make it real

    Implement the requested shape and behavior, site it carefully, and add credit. New models need real geometry, not a renamed catalogue entry.

  4. Test in the actual house

    Run npm run check:contributions -- --json, npm test, and the full geometry suite for geometry changes. Inspect desktop and phone views, the map, motion, sound and portable exports. Report what was actually checked.

  5. Offer it for review

    Submit a focused PR with screenshots, credit and source notes, checks and measured impact. Maintainers review before merging; publication is a separate step.

What the checks protect

Performance

Measured geometry and bounded data. The catalogue has an initial 128-work curation cap and a placement cap; miniature builds enforce a separate per-room vertex budget. Device performance still needs a consistent before/after comparison.

Placement

Space for the railway. Shared workshop buildings are checked against factory building footprints and the editor’s rail/water checks. Independent miniature footprints cannot overlap. Visual review covers authored terrain, roofs and camera paths.

Attribution

Plain text and deliberate links. Credits have bounded fields and supported profile hosts. Imported layout data is validated and rendered as text. Existing exported copies cannot be recalled by editing the repository.

The authoritative instructions live in AGENTS.md, CONTRIBUTING.md and the linked recipes. This atlas describes the implemented contribution path, not permission to publish.

Before public launch, follow the maintainer checklist. CODEOWNERS requests reviews; GitHub branch rules enforce required approval. File and history review remains part of launch preparation.
