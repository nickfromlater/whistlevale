# Add a train, end to end

Read [AGENTS.md](../../AGENTS.md). Establish the requested silhouette, power,
wheel arrangement, service and public credit. An original miniature design is
welcome; do not claim a licensed or accurate historical replica without support.

## Choose the implementation path

For a **finish**, add a `[name, body, lining, coach]` entry to an existing train's
`liveries` in `TRAIN_COLLECTION` (`src/trains.js`), preserving previous indices
used by saved selections. Add your credit and note. Do not reorder or delete
existing finishes casually. The checker accepts one to six finishes.

For a **train using an existing chassis**, copy the closest collection definition
under a unique lowercase `id`. Give it its own name, plate number, description,
model details, credits and finishes; check its real geometry matches the request.
The cabinet and choices discover the collection. Never change a shipped ID:
room selections and portrait filenames use it.

For a **new model family**, build the requested shape and its working parts.
Renaming a tank engine does not make it a Pacific or a diesel. Inspect these
functions before writing code:

| Concern | Source contract |
| --- | --- |
| Catalogue | `TRAIN_COLLECTION`, `collectionById`, `validateCollectionChoice` |
| Actual geometry | `collectionGeometry`, similar family builders in `src/trains.js` |
| Vehicle spacing | `collectionOffsets`, `drawSelectedCollection` |
| Working motion | `collectionWheelPhase`, `drawCollectionMotion`, `drawSelectedCollection` |
| Roofs and bogies | Existing split meshes, `collectionGeometry` result and railway transforms |
| Selection and disposal | `ensureRunningCollection`, `chooseCollectionTrain`, `applyCollectionToScene` |
| Art and preview | `initLabels` wrapper, `CabinetPreview`, `cabinetSilhouette` |
| Sound | `collectionPower`, `hobbyTrainInfo`, `src/soundscape.js` power branches |

Search for every `q.family` / `q.power` branch when adding a family; the table is
a starting map, not an assurance that one switch is enough. Keep steam rods,
quartering and driver rotation coherent. Electrics/diesels use motor sound and
horns, without steam parts. Check coupling spacing on tight curves with six
vehicles and lifted roofs. Retain builder, paint, random seed and label aliases
in `collectionGeometry`'s `finally`, and dispose replaced GPU buffers.

Use **one to six trailing vehicles**. Definition fields are `id`, `name`,
`number`, `family`, `power`, `arrangement`, `tag`, `service`, `formation`, `cars`,
`description`, `details`, `liveries`, `credits`. Formation is `coaches`, `wagons`
or `trailers`. Add coverage for the new family's mechanics rather than a test
that merely confirms the catalogue contains its ID.

## Make the portrait

Run `python3 scripts/serve.py --port 4175`. Open **Train → Choose your train**,
select the first finish, use Engine view with roofs down and wheel motion off,
and reset/framing-adjust the model so its full silhouette is visible. Under
Model details, local previews expose **Save portrait for contribution**. This
downloads a 640px WebP from the actual renderer; save it as
`assets/trains/<id>.webp` (at most 150 KB). Inspect the image and the cabinet card.
Regenerate it after changes to the default shape/finish. Portraits are never
generated by startup or build. An absent portrait can use the browsing fallback
while developing, but the contribution checker requires the finished file.

## Check and submit

```sh
npm run check:contributions -- --json
npm test
npm run test:geometry:full
```

The train suite iterates all models/finishes. Check the real model in every railway room, including The Commons,
both directions of curves, roofs, motion, steam/motor sound, shortest/longest
formation, all finishes, failed selection recovery, reload and portable export.
Inspect the map and cabinet at desktop and 390px/320px widths; test keyboard focus,
Escape, drag and touch. Compare `?profile` using the same device and camera.

Supply screenshots, the actual test results, geometry/performance impact, chosen
credit and source/permission notes in the PR. Describe any unverified physical
device behavior. Discuss an unusually large train or new mechanics first. Do
not deploy the contribution from a fork or change the upstream repository settings.

Use the [local review guide](review.md) for evidence storage, comparable runtime
measurements and the complete-house export menu route.
